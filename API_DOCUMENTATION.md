## Operator Controller APIs

### `GET /serviceoperators`
- **Description**: Retrieves a list of all available service operators.
- **Request**:
    - Path Variables: None
    - Parameters: None
    - Body: None
- **Response**:
    - Success: `200 OK` - `List<ServiceOperator>`
        ```json
        [
          {
            "id": 1,
            "name": "Operator Name 1"
          },
          {
            "id": 2,
            "name": "Operator Name 2"
          }
        ]
        ```
    - Error: `500 Internal Server Error` - Standard Spring Boot error response if an unexpected server-side issue occurs.
- **Service Logic (`OperatorService.getAllServiceOperators`)**:
    - This method is responsible for fetching all `ServiceOperator` entities. It directly calls the `findAll()` method of the `ServiceOperatorRepository` and returns the retrieved list. No additional business logic or validation is performed within this service method.
- **Repository Interaction (`ServiceOperatorRepository.findAll`)**:
    - This is an inherited method from `JpaRepository<ServiceOperator, Long>`.
    - It performs a database query (e.g., `SELECT * FROM service_operator`) to select all records from the `service_operator` table and maps them to a `List<ServiceOperator>` objects.
- **Models/DTOs Used**:
    - `ServiceOperator`:
        - `id` (Long): The unique identifier of the service operator.
        - `name` (String): The name of the service operator.

### `GET /serviceoperators/{id}`
- **Description**: Retrieves a specific service operator by their ID.
- **Request**:
    - Path Variables: `id (Long)` - The ID of the service operator to retrieve.
    - Parameters: None
    - Body: None
- **Response**:
    - Success: `200 OK` - `ServiceOperator`
        ```json
        {
          "id": 1,
          "name": "Operator Name"
        }
        ```
    - Error: `404 Not Found` - If the service operator with the given ID does not exist. The `orElseThrow()` (defaulting to `NoSuchElementException`) in the service layer is typically handled by Spring Boot's default exception handlers to return a 404 HTTP status with a standard error body.
    - Error: `500 Internal Server Error` - Standard Spring Boot error response for other unexpected server-side issues.
- **Service Logic (`OperatorService.getServiceOperatorByID`)**:
    - This method accepts a `Long id` as input.
    - It calls `serviceOperatorRepository.findById(id)` to find the operator.
    - If the operator is not found, `orElseThrow()` is called (which defaults to throwing `NoSuchElementException`).
    - If found, it returns the `ServiceOperator` object.
- **Repository Interaction (`ServiceOperatorRepository.findById`)**:
    - This is an inherited method from `JpaRepository<ServiceOperator, Long>`.
    - It performs a database query (e.g., `SELECT * FROM service_operator WHERE id = :id`) to select a record by its primary key. Returns an `Optional<ServiceOperator>`.
- **Models/DTOs Used**:
    - `ServiceOperator`:
        - `id` (Long): The unique identifier of the service operator.
        - `name` (String): The name of the service operator.

### `POST /serviceoperators`
- **Description**: Creates a new service operator.
- **Request**:
    - Path Variables: None
    - Parameters: None
    - Body: `ServiceOperator`
        ```json
        {
          "name": "New Operator Name"
        }
        ```
        *(Note: The `id` field is typically not provided in the request body as it's auto-generated by the database.)*
- **Response**:
    - Success: `201 Created` - `ServiceOperator` (Controller returns `ResponseEntity.ok()`, which is `200 OK`. Standard REST practice suggests `201 Created` for new resources.)
        ```json
        {
          "id": 3,
          "name": "New Operator Name"
        }
        ```
    - Error: `400 Bad Request` - If the request body is malformed or missing required fields (if specific DTO validations were implemented).
    - Error: `500 Internal Server Error` - Standard Spring Boot error response for unexpected server-side issues.
- **Service Logic (`OperatorService.createServiceOperator`)**:
    - This method takes a `ServiceOperator` object (containing the `name`) as input.
    - It directly calls `serviceOperatorRepository.save(serviceOperator)` to persist the new entity.
    - The `save` method handles the SQL `INSERT` operation, and the database auto-generates the `id`.
    - The saved `ServiceOperator` entity (now including its `id`) is returned.
- **Repository Interaction (`ServiceOperatorRepository.save`)**:
    - This is an inherited method from `JpaRepository<ServiceOperator, Long>`.
    - For a new entity (where `id` is null or not yet persisted), it performs an SQL `INSERT` operation.
- **Models/DTOs Used**:
    - `ServiceOperator`:
        - `id` (Long): The unique identifier of the service operator (auto-generated and returned).
        - `name` (String): The name of the service operator.

### `PUT /serviceoperators/{id}`
- **Description**: Updates an existing service operator's information.
- **Request**:
    - Path Variables: `id (Long)` - The ID of the service operator to update.
    - Parameters: None
    - Body: `ServiceOperator`
        ```json
        {
          "name": "Updated Operator Name"
        }
        ```
        *(Note: The `id` in the request body, if present, is typically ignored or should match the path variable `id`.)*
- **Response**:
    - Success: `200 OK` - `ServiceOperator`
        ```json
        {
          "id": 1,
          "name": "Updated Operator Name"
        }
        ```
    - Error: `404 Not Found` - If the service operator with the given `id` does not exist. The `orElseThrow(() -> new RuntimeException("ServiceOperator not found"))` in the service would typically be converted to a 404 HTTP status by Spring's default exception handlers.
    - Error: `400 Bad Request` - If the request body is malformed.
    - Error: `500 Internal Server Error` - Standard Spring Boot error response for unexpected server-side issues.
- **Service Logic (`OperatorService.updateServiceOperator`)**:
    - Accepts the `Long id` (from path) and `ServiceOperator updatedServiceOperator` (from body).
    - Retrieves the `existingServiceOperator` using `serviceOperatorRepository.findById(id)`.
    - If not found, `orElseThrow(() -> new RuntimeException("ServiceOperator not found"))` is triggered.
    - If found, it updates the `name` of the `existingServiceOperator` using the value from `updatedServiceOperator.getName()`.
    - Calls `serviceOperatorRepository.save(existingServiceOperator)` to persist the changes.
    - The updated `ServiceOperator` entity is returned.
- **Repository Interaction (`ServiceOperatorRepository.findById` and `ServiceOperatorRepository.save`)**:
    - `findById(id)`: Fetches the operator by ID.
    - `save(existingServiceOperator)`: For an existing entity (with a valid `id`), this performs an SQL `UPDATE` operation.
- **Models/DTOs Used**:
    - `ServiceOperator`:
        - `id` (Long): The unique identifier of the service operator.
        - `name` (String): The name of the service operator.

## Scheduler Controller APIs

### `POST /book`
- **Description**: Books a new appointment with a specific service operator for a given start hour.
- **Request**:
    - Path Variables: None
    - Parameters: None
    - Body: `AppointmentRequestDTO`
        ```json
        {
          "operatorId": 1,
          "startHour": 9
        }
        ```
- **Response**:
    - Success: `201 CREATED` - `ResponseEntity<Object>` (via `ResponseHandler`)
        ```json
        {
            "timestamp": "YYYY-MM-DDTHH:mm:ss.sssZ",
            "status": 201,
            "isSuccess": true,
            "message": "Slot Booked",
            "data": {
                "id": 1,
                "serviceOperator": {
                    "id": 1,
                    "name": "Operator Name"
                },
                "startHour": 9,
                "endHour": 10
            }
        }
        ```
    - Error: `400 BAD_REQUEST` - `ResponseEntity<Object>` (via `ResponseHandler`)
        ```json
        {
            "timestamp": "YYYY-MM-DDTHH:mm:ss.sssZ",
            "status": 400,
            "isSuccess": false,
            "message": "Invalid start time", // or "Slot already filled for this operator"
            "data": null
        }
        ```
    - Error: `404 Not Found` - If the specified `operatorId` does not exist (service calls `operatorService.getServiceOperatorByID` which can throw if not found, leading to a 404).
- **Service Logic (`SchedulerService.bookAppointment`)**:
    - Retrieves `operatorId` and `startHour` from the `AppointmentRequestDTO`.
    - **Validation**: Checks if `startHour` is valid (0-23). If not, returns a "Invalid start time" response using `ResponseHandler`.
    - Calls `operatorService.getServiceOperatorByID(operatorId)` to fetch the `ServiceOperator`. This will throw an exception if the operator is not found.
    - Calls its private method `isSlotAvailable(operatorId, startHour)` to check for conflicts.
        - `isSlotAvailable` queries `AppointmentRepository.findByOperatorIdAndStartHourBetween(operatorId, startHour)`.
    - If the slot is available:
        - Creates a new `Appointment` entity.
        - Sets the fetched `serviceOperator`, `startHour`, and `endHour` (as `startHour + 1`).
        - Saves the appointment using `appointmentRepository.save(appointment)`.
        - Returns a "Slot Booked" success response (HTTP 201) via `ResponseHandler` with the created `Appointment` data.
    - If the slot is not available, returns a "Slot already filled for this operator" error response (HTTP 400) via `ResponseHandler`.
- **Repository Interaction**:
    - `ServiceOperatorRepository.findById(operatorId)`: (Called via `operatorService`) Fetches the `ServiceOperator`.
    - `AppointmentRepository.findByOperatorIdAndStartHourBetween(operatorId, startHour)`: Custom query `SELECT a.id FROM Appointment a JOIN a.serviceOperator ap WHERE ap.id = :operatorId and a.startHour = :startHour`. Checks if an appointment exists for the operator at the specified hour.
    - `AppointmentRepository.save(appointment)`: Inherited. Saves the new `Appointment` entity (SQL INSERT).
- **Models/DTOs Used**:
    - `AppointmentRequestDTO`:
        - `operatorId` (long): The ID of the service operator.
        - `startHour` (int): The desired start hour for the appointment.
    - `Appointment`:
        - `id` (Long): The unique identifier of the appointment.
        - `serviceOperator` (ServiceOperator): The assigned service operator.
        - `startHour` (int): The start hour of the appointment.
        - `endHour` (int): The end hour of the appointment.
    - `ServiceOperator`:
        - `id` (Long): The unique identifier of the operator.
        - `name` (String): The name of the operator.

### `PUT /reschedule/{id}`
- **Description**: Reschedules an existing appointment to a new time and/or with a new (or same) operator.
- **Request**:
    - Path Variables: `id (Long)` - The ID of the appointment to be rescheduled.
    - Parameters: None
    - Body: `AppointmentRequestDTO`
        ```json
        {
          "operatorId": 1,
          "startHour": 10
        }
        ```
- **Response**:
    - Success: `200 OK` - `ResponseEntity<Object>` (via `ResponseHandler`)
        ```json
        {
            "timestamp": "YYYY-MM-DDTHH:mm:ss.sssZ",
            "status": 200,
            "isSuccess": true,
            "message": "Appointment rescheduled successfully",
            "data": {
                "id": 1, // Existing appointment ID
                "serviceOperator": {
                    "id": 1,
                    "name": "Operator Name"
                },
                "startHour": 10, // New start hour
                "endHour": 11
            }
        }
        ```
    - Error: `400 BAD_REQUEST` - `ResponseEntity<Object>` (via `ResponseHandler`) for "Invalid start time" or "New time slot not available".
    - Error: `404 Not Found` - `ResponseEntity<Object>` (via `ResponseHandler` or Spring default) if the appointment ID or operator ID specified in the DTO does not exist (service throws `RuntimeException`).
- **Service Logic (`SchedulerService.rescheduleAppointment`)**:
    - Accepts `appointmentId` (from path) and `AppointmentRequestDTO` (from body).
    - Fetches the existing `Appointment` using `appointmentRepository.findById(appointmentId)`. Throws `RuntimeException("Appointment not found")` if not found.
    - Fetches the `ServiceOperator` (for the new schedule) using `serviceOperatorRepository.findById(appointmentRequestDTO.getOperatorId())`. Throws `RuntimeException("Service Operator not found")` if not found.
    - **Validation**: Checks if `newStartHour` from DTO is valid (0-23). If not, returns "Invalid start time" via `ResponseHandler`.
    - Calls `isSlotAvailable(serviceOperator.getId(), newStartHour)` to check availability.
    - If available:
        - Updates the existing `Appointment`'s `serviceOperator`, `startHour`, and `endHour`.
        - Saves the updated appointment using `appointmentRepository.save(appointment)`.
        - Returns "Appointment rescheduled successfully" (HTTP 200) via `ResponseHandler`.
    - If not available, returns "New time slot not available" (HTTP 400) via `ResponseHandler`.
- **Repository Interaction**:
    - `AppointmentRepository.findById(appointmentId)`: Inherited. Fetches the existing appointment.
    - `ServiceOperatorRepository.findById(operatorId)`: Inherited. Fetches the `ServiceOperator`.
    - `AppointmentRepository.findByOperatorIdAndStartHourBetween(operatorId, startHour)`: (Called by `isSlotAvailable`) Custom query.
    - `AppointmentRepository.save(appointment)`: Inherited. Saves the updated `Appointment` (SQL UPDATE).
- **Models/DTOs Used**:
    - `AppointmentRequestDTO`: (As above)
    - `Appointment`: (As above)
    - `ServiceOperator`: (As above)

- **Request**:
    - Path Variables: None
    - Parameters: `oid (Long)` - The ID of the service operator.
    - Body: None
- **Response**:
    - Success: `200 OK` - `List<String>`
        ```json
        [
            "0-9",
            "10-14",
            "15-24"
        ]
        ```
    - Error: `404 Not Found` - If the `ServiceOperator` with the given `oid` is not found (service throws `RuntimeException` from `orElseThrow`).

    - Iterates through the `occupied` array to find contiguous free slots and formats them as "startHour-endHour" strings.
    - Returns the `List<String>` of open slots.
- **Repository Interaction**:
    - `ServiceOperatorRepository.findById(operatorId)`: Inherited. Fetches the operator.
    - `AppointmentRepository.findByServiceOperator(ServiceOperator so)`: Derived query.
- **Models/DTOs Used**:
    - `Appointment`: (Used internally)

### `POST /book-any`
- **Description**: Books an appointment at a specific time with any available service operator.
- **Request**:
    - Path Variables: None
    - Parameters: None
    - Body: `BookAnyRequestDTO`
        ```json
        {
          "startHour": 14
        }
        ```
- **Response**:
    - Success: `201 CREATED` - `ResponseEntity<Object>` (via `ResponseHandler`)
        ```json
        {
            "timestamp": "YYYY-MM-DDTHH:mm:ss.sssZ",
            "status": 201,
            "isSuccess": true,
            "message": "Slot Booked with operator Operator Name",
            "data": {
                "id": 5,
                "serviceOperator": {
                    "id": 2,
                    "name": "Operator Name"
                },
                "startHour": 14,
                "endHour": 15
            }
        }
        ```
    - Error: `400 BAD_REQUEST` - `ResponseEntity<Object>` (via `ResponseHandler`) for "Invalid start time".
    - Error: `404 NOT_FOUND` - `ResponseEntity<Object>` (via `ResponseHandler`) for "No service operators found in the system."
    - Error: `409 CONFLICT` - `ResponseEntity<Object>` (via `ResponseHandler`) for "No operator available for the selected time slot."
- **Service Logic (`SchedulerService.bookAppointmentWithAnyOperator`)**:
    - Retrieves `startHour` from `BookAnyRequestDTO`.
    - **Validation**: Checks if `startHour` is valid (0-23). If not, returns "Invalid start time" (HTTP 400) via `ResponseHandler`.
    - Fetches all `ServiceOperator`s using `operatorService.getAllServiceOperators()`.
    - If no operators exist, returns "No service operators found..." (HTTP 404) via `ResponseHandler`.
    - Iterates through each `ServiceOperator`:
        - Calls `isSlotAvailable(operator.getId(), startHour)`.
        - If a slot is found:
            - Creates and saves a new `Appointment` with this operator.
            - Returns a "Slot Booked with operator [Name]" (HTTP 201) via `ResponseHandler`.
    - If no operator is available, returns "No operator available..." (HTTP 409) via `ResponseHandler`.
- **Repository Interaction**:
    - `ServiceOperatorRepository.findAll()`: (Called via `operatorService`) Fetches all operators.
    - `AppointmentRepository.findByOperatorIdAndStartHourBetween(operatorId, startHour)`: (Called by `isSlotAvailable`) Custom query.
    - `AppointmentRepository.save(appointment)`: Inherited. Saves the new `Appointment`.
- **Models/DTOs Used**:
    - `BookAnyRequestDTO`:
        - `startHour` (int): The desired start hour.
    - `Appointment`: (As above)
    - `ServiceOperator`: (As above)

## Utility Classes

### ResponseHandler
- **Class Name:** `ResponseHandler`
- **Package:** `com.voltmoney.carservicescheduler.utils`
- **Overall Purpose:** The `ResponseHandler` class is a utility designed to standardize the structure of HTTP responses across the application. It provides a static method to generate `ResponseEntity<Object>` objects with a consistent JSON format, making API responses predictable and easier for clients to consume. This is particularly useful for wrapping service layer outcomes into formatted HTTP responses in the controller layer.

---

#### Public Static Methods

##### 1. `generateResponse(HttpStatus status, boolean error, String message, Object responseObj)`

-   **Method Signature:**
    ```java
    public static ResponseEntity<Object> generateResponse(
        HttpStatus status,
        boolean error,
        String message,
        Object responseObj
    )
    ```

-   **Parameters:**
    -   `status` (`org.springframework.http.HttpStatus`): The HTTP status code for the response (e.g., `HttpStatus.OK`, `HttpStatus.BAD_REQUEST`, `HttpStatus.CREATED`). This determines the HTTP status of the `ResponseEntity`.
    -   `error` (`boolean`): A boolean flag indicating whether the response represents an error state. If `true`, it signifies an error; if `false`, it signifies a successful operation. This flag is used to set the `isSuccess` field in the response body (which will be the inverse of `error`).
    -   `message` (`String`): A descriptive message to be included in the response body. This can be a success message, an error message, or any relevant information for the client.
    -   `responseObj` (`Object`): The actual data payload to be included in the response. This can be any object (e.g., a DTO, an entity, a list of items, or `null` if no specific data needs to be returned beyond the message).

-   **Description:**
    This method constructs a `ResponseEntity<Object>` that wraps a standardized map structure as its body. It takes the provided HTTP status, an error flag, a message, and a data payload to build this response. The primary goal is to ensure all API responses have a common structure.

-   **Generated JSON Response Structure:**
    The method creates a `java.util.Map<String, Object>` which is then serialized to a JSON object by Spring MVC. The structure of this JSON object is as follows:

    ```json
    {
        "timestamp": "YYYY-MM-DDTHH:mm:ss.sssZ", // Example: Current date and time when the response was generated
        "status": 200,                           // Example: HTTP status code value (e.g., 200, 400, 201)
        "isSuccess": true,                       // Example: Boolean, true if 'error' param was false, false otherwise
        "message": "Operation completed successfully", // Example: The message string passed to the method
        "data": {                                // Example: The 'responseObj' passed to the method
            "key": "value"
        }
        // or "data": null, if responseObj was null
        // or "data": [...] if responseObj was a list
    }
    ```

    -   `timestamp`: The date and time when the response map was created.
    -   `status`: The integer value of the `HttpStatus` (e.g., `200` for `OK`, `400` for `BAD_REQUEST`).
    -   `isSuccess`: A boolean value that is the logical NOT of the `error` parameter (i.e., `!error`). `true` indicates success, `false` indicates an error.
    -   `message`: The custom message string.
    -   `data`: The payload object. If `responseObj` is `null`, this field will also be `null`.
---
